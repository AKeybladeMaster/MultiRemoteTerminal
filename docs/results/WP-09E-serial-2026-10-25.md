# WP-09E acceptance evidence: Windows serial/COM terminal

**Date:** 2026-10-25. **Status:** Partial. **Requirements:** F-016, P-12.

## Delivered

- Added a COM-only domain configuration contract with canonical paths and bounded baud, data bits, parity, stop bits, flow control, port metadata and terminal input.
- Added application session lifecycle, strict versioned utility-worker messages, a supervised worker host, and a native serial transport adapter.
- Loaded `@serialport/stream@13.0.0` and `@serialport/bindings-cpp@13.0.1` only in the worker. The renderer uses allowlisted typed IPC for list, open, write, paste, resize, output acknowledgement and close.
- Added a connection dialog with port refresh and serial settings. Connected sessions support terminal input/output, terminal-tab context actions, middle-click close and Ctrl+W.
- Added focused tests for configuration and port-list bounds, IPC and worker message validation, application lifecycle, and mock-binding read/write/ack/close.

The E2E launches the unpackaged app with the explicit test-only `--mrt-e2e-serial-mock` argument and `MRT_E2E=1`. The worker loads the native Windows binding and enumerates native ports alongside a deterministic `COM4095` mock, but the test opens only the mock port. No physical COM device was opened.

Electron-builder skipped code signing because no signing certificate is configured. Package smoke verifies local build, install/launch and native port enumeration; it does not complete signing or signature verification.

## Remaining acceptance

The result does not verify a physical USB/UART adapter, device-specific text/binary handling, serial driver signature policy, hot-unplug/reconnect behavior, or broader device interoperability. The provider currently renders received bytes as UTF-8 terminal text. Saved serial definitions and folder bundle round-trip are deferred to the next slice. F-016 and P-12 therefore remain PARTIAL.
