# WP-01E: Git Bash terminal

**Requirements:** F-002; partial progress toward P-02.
**Platform:** Windows 11 x64, Node 24.14.1, Electron 45.0.0, installed Git for Windows.
**Status:** Passed Windows build and Electron acceptance. P-02 remains partial; this does not establish release readiness.

## Delivered behavior

- The command palette opens an explicitly selected Bash terminal through the existing ConPTY utility worker.
- The worker resolves only `<Git>\\bin\\bash.exe` from standard machine-wide or per-user install roots. This uses the Git for Windows wrapper, does not consult arbitrary `PATH` entries, and cannot select the `System32\\bash.exe` WSL launcher.
- Bash is started as a login, interactive shell with `--login -i`; commands are not composed into a shell command line by the application.
- The shell type is accepted by the validated terminal contract and persisted session catalog. The saved-session list and terminal tabs identify Bash distinctly, and a missing Git for Windows installation produces a clear user-facing message.
- No package dependency or bundled Git runtime was added.

## Validation

- `corepack pnpm typecheck` — passed.
- `corepack pnpm lint` — passed, including static import-boundary checks.
- `corepack pnpm test` — 97 passed, 0 failed.
- `corepack pnpm build` — passed on Windows x64; Vite emitted the existing renderer chunk-size advisory.
- Focused `corepack pnpm exec playwright test --grep "Git Bash"` — passed; the test ran a Bash-version command, saved the definition, reopened it, and ran the command again.
- `corepack pnpm check` — passed: typecheck, lint/import boundaries, 97 unit and adapter tests, Windows x64 build, and all 12 Electron E2E tests. The E2E suite also covered the existing local shells, saved-session persistence, tab interactions, and application security policy.

## Limitations

Git for Windows must be installed in one of the standard roots for Bash to be available. Custom installation paths and WSL integration are not supported. Broader Unix-tool acceptance remains future work, so P-02 is partial. The Windows acceptance evidence comes from the configured Windows 11 x64 machine; it does not complete the full F-002 release gate or validate packaging.
