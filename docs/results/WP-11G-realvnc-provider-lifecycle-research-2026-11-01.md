# WP-11G feasibility research: RealVNC Viewer provider lifecycle

**Reviewed:** 2026-11-01
**Scope:** F-017 fixed third-party provider discovery, installation, update, and removal
**Status:** Research only; no product implementation, download, installation, or acceptance

## Decision

RealVNC is **not currently a suitable app-managed drop-in replacement** for the existing TigerVNC provider. It is a technically plausible separate, opt-in provider if users accept RealVNC's account and paid-plan requirements and the remaining artifact and installation details are verified. Keep F-017 and P-08 PARTIAL; this report makes no acceptance claim.

RealVNC provides a better integrity basis than the current TigerVNC candidate: its first-party checksum page now lists RealVNC Connect Viewer 8.5.3 for Windows as an MSI and publishes its SHA-256 (`9047166ea784f306abb54c932198144c338397b7bc755a72d8107708d268a31b`). RealVNC also issued 8.5.3 as the patched release in its October 2026 certificate-incident notice. A release pinned to that exact vendor hash could reject altered downloads. The vendor page is a checksum list, not a signed release manifest, and the reviewed first-party material did not identify the current Viewer MSI's Authenticode subject or certificate pin. The exact static download URL for the versioned MSI was not verified; an older official latest-MSI link returned 404 during this review. [RealVNC v8 checksums](https://help.realvnc.com/hc/en-us/articles/27252822630301-SHA256-checksums-for-RealVNC-Connect-v8), [patched release notice](https://help.realvnc.com/hc/en-us/articles/40122131868829-Action-required-Update-your-RealVNC-applications-third-party-certificate-issue), [Windows MSI deployment instructions](https://help.realvnc.com/hc/en-us/articles/360002250657-Deploying-and-Licensing-RealVNC-Connect-using-Windows-MSIs)

The documented viewer launch model fits the existing application-level provider interface: RealVNC Viewer accepts a target on its command line, and current RealVNC documentation uses `host::port` for a non-default port. The existing adapter formats this target and launches without a shell. It does **not** fit the existing TigerVNC-specific executable resolver unchanged: the resolver only checks TigerVNC paths. A RealVNC provider would need a distinct, fixed discovery rule. RealVNC documents `C:\Program Files\RealVNC\VNC Viewer` as the default Viewer directory in its general command-line guide, but that guide predates v8.4; the v8.5.3 Viewer install path remains to be verified against the current package before adding a fixed resolver. [RealVNC Viewer command reference](https://help.realvnc.com/hc/en-us/articles/360002253218-Starting-and-Stopping-RealVNC-Connect), [direct connection guide](https://help.realvnc.com/hc/en-us/articles/38538874117533-RealVNC-Viewer-and-Server-Basics)

## Lifecycle and product limitations

- RealVNC documents separate Windows Viewer MSIs, `msiexec` deployment, update-by-installing the newer release, and standard Windows uninstall through Programs and Features. The documented Windows removal path requires administrator privileges and may require a restart. These sources establish a user-visible MSI lifecycle, but not safe app-owned install attribution, per-user install scope, a current Viewer MSI product identity, or a documented silent Viewer uninstall command. Do not add a guessed package identity or silently remove an installation the app did not create. [Windows MSI deployment instructions](https://help.realvnc.com/hc/en-us/articles/360002250657-Deploying-and-Licensing-RealVNC-Connect-using-Windows-MSIs), [install and removal guide](https://help.realvnc.com/hc/en-us/articles/360002253198-Installing-and-Removing-RealVNC-Connect-Advanced-users), [update guide](https://help.realvnc.com/hc/en-us/articles/29008743984157-How-do-I-update-RealVNC-Connect)
- RealVNC Connect Viewer 8.4+ requires an account sign-in. Its release notes say connections to non-RealVNC servers are limited to Essentials, Plus, Premium, or Enterprise plans. The free Lite plan therefore does not meet this product's general third-party VNC use case. Classic Viewer 7 remains available only to Premium or Enterprise customers through the signed-in portal. [Viewer changes and plan limits](https://help.realvnc.com/hc/en-us/articles/35745908986653-Important-changes-to-RealVNC-Viewer-Information-and-FAQs), [Viewer 8.4 release notes](https://help.realvnc.com/hc/en-us/articles/35693482773021-RealVNC-Viewer-8-4-0-8-4-1)
- RealVNC's published EULA grants use subject to subscription capacity and says users may not distribute the software except under specified managed-service terms. The download page also makes the downloader accept RealVNC's terms and privacy policy. Do not bundle or redistribute the Viewer, and obtain a specific licensing review before adding an app-managed download/install flow. [RealVNC EULA](https://www.realvnc.com/wp-content/uploads/2025/05/RealVNC-End-User-Licensing-Agreement-08.05.2025.pdf), [Viewer download page](https://www.realvnc.com/en/connect/download/viewer/windows/)
- RealVNC says its all-in-one Connect app conflicts with installing the separate Connect Viewer; its update guide says the all-in-one app must be uninstalled first and that this clears configuration. An app-managed flow must detect and preserve existing installations and must not silently uninstall or replace the all-in-one app. [RealVNC update guide](https://help.realvnc.com/hc/en-us/articles/29008743984157-How-do-I-update-RealVNC-Connect)

## Remaining evidence before reconsideration

1. Verify the versioned 8.5.3 Viewer download URL from a current RealVNC page and retrieve the artifact without executing it; compare its SHA-256 to the official list.
2. Inspect the downloaded MSI and installed application for Authenticode publisher identity, architecture, product identity, fixed installation path, and upgrade/removal behavior. Vendor documentation reviewed here did not publish Viewer-specific signer identity or those package details.
3. Decide whether a paid-plan/account-dependent provider belongs in the product's general VNC workflow; do not imply that the free Lite plan can connect to third-party servers.
4. Resolve legal terms for app-managed delivery, and define explicit consent and removal ownership before implementation.
5. If selected, add it as a fixed provider under the existing launch interface, preserve host/port validation and shell-free argument handling, and run live Windows interoperability acceptance only at the complete Phase 08 verification gate.

No files other than this research report were changed for WP-11G. No installer was downloaded or executed, no Authenticode check or VNC interoperability test was performed, and no automated tests were run.

## 2026-11-01 official download follow-up

The current RealVNC checksum page confirms the Windows Viewer MSI 8.5.3 filename and SHA-256 recorded above, and the first-party patched-release notice lists Viewer 8.5.3. A direct read-only request from the local Windows host to the official Viewer download page returned HTTP 403, so no MSI URL or artifact was retrieved and no signature, package identity, or install path was inspected. The paid-plan/account limitations for third-party VNC connections remain independently documented by RealVNC's Viewer FAQ. This does not change the decision: keep the existing TigerVNC user-installed provider and F-017 PARTIAL.
