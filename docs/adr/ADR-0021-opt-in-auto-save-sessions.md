# ADR-0021 — Opt-in automatic saved-session updates

- **Status:** Accepted
- **Date:** 2026-10-25
- **Context:** P-13 needs an automatic saved-session workflow without surprising users or adding secrets to persistent definitions. Existing workbench settings are versioned in SQLite, the session catalog has credential-free validated records, and the renderer must not be the authority for privacy preferences.
- **Decision:** Add an off-by-default `autoSaveSessions` preference in workbench settings schema v3. After a successful in-app terminal or file connection, the renderer may issue the typed `session.remember` command. The main-process broker reads the persisted preference and rejects the command unless it is enabled. The storage worker normalizes the definition and reuses an existing record with the same protocol kind, canonical endpoint and protocol options, updating its last-used timestamp; otherwise it creates a new credential-free record. Startup's automatically created PowerShell session is excluded.
- **Scope:** Direct local, SSH, SFTP, Telnet, FTP/FTPS and serial connections are remembered. SSH connections routed through gateways are skipped because the saved-session schema does not contain route selections. RDP/VNC handoffs are skipped because the workbench cannot verify a connection to the remote desktop. Manually saved profiles and saved-folder bundle schemas do not change.
- **Safety:** The setting defaults off and is persisted per local app profile. The command accepts only the existing exact saved-session draft shape; secrets, terminal text and paths cannot be included. A denied or failed remember operation does not close the live connection. The user can delete an auto-saved entry using the existing saved-session action.
- **Consequences:** Reopening a matching definition preserves its name, folder and favorite state while updating its recency. No database schema migration is required for the catalog. Workbench preference records at schema versions 1 and 2 migrate to version 3 with auto-save disabled. The feature does not claim the 1,000-definition Windows workflow required by F-004/P-38.
- **Verification:** Focused domain, SQLite, storage-protocol, IPC and broker tests verify v1/v2 preference migration, opt-in enforcement, normalized idempotent matching and credential-free records. Windows E2E verifies an explicit opt-in, first save, deduplication after another open, restart persistence and the retained preference. See [WP-03E results](../results/WP-03E-auto-save-sessions-2026-10-25.md).
