# ADR-0003 — WP-02 interim host identity and credential storage

**Status:** Accepted for WP-02, with migration required in WP-03 (2026-10-23)

## Context

WP-02 must remember SSH host identities and encrypted credentials before the SQLite session catalog in WP-03 exists. Silently accepting unknown or changed SSH host keys is unsafe. Storing credentials in a plain JSON file or session definition is prohibited. Electron 45 exposes asynchronous `safeStorage` in the main process; on Windows its key provider uses DPAPI and protects data from other Windows users, but not from malware running as the same user.

## Decision

- Keep host-identity and credential-vault interfaces in the application layer. Implement their adapters under `apps/desktop/src/adapters/`; the Electron main composition root constructs and wires them. The renderer receives host-key challenge evidence, credential labels/references, and terminal events, but never reads a stored secret.
- Acquire Electron's single-instance lock before initializing the host-identity or credential-vault adapters. A second app process exits before reading or mutating their files; the process-local host-store queue then serializes every host-key writer.
- Secret entry uses an explicit user action that requests a fixed Windows PowerShell 5.1 helper to show the native `Get-Credential` dialog. Main obtains the system directory from Win32 `GetSystemDirectoryW` through a small repository-owned Node-API bridge; it never trusts inherited `SystemRoot` or `WINDIR`. Append the fixed `WindowsPowerShell\v1.0\powershell.exe` relative path, fail closed if the API fails or the resulting absolute executable is absent, and launch with `shell: false`, fixed arguments including `-NoProfile`, and no execution-policy override. This prevents user profiles from running before the prompt. The renderer sends only non-secret target metadata and receives only a credential reference/status; the helper returns the response through a private one-shot stdout pipe to main. Never put credentials in process arguments, helper stdin, files, renderer IPC, logs, PowerShell's normal output stream, or events. The helper does not persist credentials, writes a bounded response directly to the inherited pipe, reports cancellation without a secret, and exits after one prompt. Main clears temporary mutable buffers after storing or handing off a credential. Private-key selection and file reads stay in main; key passphrases and master passwords use the same prompt. Agent authentication has no password prompt.
- Until WP-03 introduces the SQLite storage worker and `ssh_host_keys` table, persist host identity metadata in a versioned JSON file under `app.getPath('userData')`. Canonicalize DNS names to lowercase and remove one trailing dot; lowercase IPv6 text and retain the explicit port. Store the canonical host, port, key algorithm, public key, SHA-256 fingerprint, trust time and approval source. Serialize reads and mutations through one process-local queue shared by all adapter instances targeting the same canonical path and capped at 128 pending operations, then update the file through an atomic temp-file replacement; reject a store larger than 16 MiB before parsing or replacing it. A malformed or unsupported file fails closed; it never causes a host to be trusted.
- Unknown-host approvals live in main-process memory for at most two minutes, with at most 64 pending or persisting challenges. The challenge token binds the exact endpoint and key evidence. The renderer receives only the token, canonical host, port, algorithm and fingerprint, never the public-key blob. Reject, disconnect, expiry or window teardown removes any unclaimed pending approval. The explicit approve action consumes its token synchronously before asynchronous persistence, so a later reject cannot report success while that already accepted decision is still writing. The handshake waits at most 15 seconds for trust-store persistence; timeout fails the active handshake, while an already-started filesystem operation cannot be cancelled and may complete the explicitly approved save later. Window teardown resolves active handshake waiters as cancelled without rolling back an approval already claimed. Approval uses an atomic insert-if-absent store operation: concurrent approvals for the same endpoint and different keys cannot replace the first trusted key.
- The default vault mode persists per-secret ciphertext produced by `safeStorage.encryptStringAsync`. Fail closed if async encryption is unavailable. Never write plaintext secrets to disk, logs, command replies, or events. Decrypt only in main for a single operation and pass the result to the network utility worker over its private parent channel. If `safeStorage.decryptStringAsync` requests re-encryption, atomically replace that stored envelope with the newly encrypted value.
- Provide optional master-password mode with `libsodium-wrappers-sumo`'s Argon2id and XChaCha20-Poly1305 APIs behind the vault adapter. Version-1 vault envelope profile is fixed: Argon2id 1.3, opslimit 2, memlimit 67,108,864 bytes (64 MiB), 16-byte random salt, and 32-byte derived key; each entry uses a fresh random 24-byte XChaCha20-Poly1305 nonce and the library's 16-byte authentication tag. Persist all parameters, nonce and ciphertext; bind the envelope version, profile and credential reference as associated data. The unlock check is an authenticated encrypted sentinel. Accept only the exact version-1 profile and expected encoded lengths; malformed or unknown parameters fail closed before KDF work. A future profile requires a versioned migration and tests.
- Libsodium password derivation is synchronous. Run each bounded derivation in a dedicated short-lived Electron utility process, not the main event loop or SSH worker. The process receives only the one-shot password and salt, returns only the 32-byte derived key over its private channel, zeroes mutable inputs where possible, and exits. Main retains the key. Bound the operation to 30 seconds; on timeout or lock, terminate the process and discard its result. A monotonic unlock-generation token prevents a late result from undoing a manual/idle/OS lock; zero any stale returned key buffer.
- `vault.lock` blocks secret resolution in both modes. DPAPI mode starts available after app startup and explicit unlock re-enables resolution after a lock; this is an app privacy control, not an additional authentication boundary. Master-password mode starts locked after every restart and requires the native prompt. Serialize every vault read/write operation that can mutate state—including save, delete, safeStorage key rotation, and credential resolution—through one adapter-owned queue. Mode conversion takes exclusive ownership of this queue from snapshot through verification and atomic replacement so concurrent saves cannot be lost and readers see one complete mode. It stages full re-encryption in a temporary ciphertext vault, decrypts each staged entry and compares it byte-for-byte with its source value in memory, then atomically replaces the prior vault only after every reference passes. Any failure keeps the previous mode and data intact and removes the temporary file. No plaintext staging file is permitted.
- Lock manually, after 15 minutes without a validated user-initiated app command, and immediately on Windows session lock or suspend. Master-password lock zeroes the derived key's mutable byte buffer; every lock makes new secret resolution unavailable. Already authenticated SSH transports may stay connected, but must not retain reusable credentials after authentication. After five failed unlocks, block attempts for 30 seconds; each further group of five doubles the delay up to 15 minutes. Persist the next allowed attempt time so restarting does not reset the delay; a successful unlock clears the counter. Never send the master password or derived key to the SSH worker. JavaScript strings and runtime copies cannot be guaranteed erased; keep their lifetime short and make no hard memory-erasure claim.
- There is no master-password recovery or escrow. If the password is lost, the user may explicitly reset the vault, which deletes encrypted credentials permanently; session definitions remain, and credentials must be entered again. A backup of the encrypted vault is unusable without its master password.
- `libsodium` supplies the maintained, high-level Argon2id and authenticated-encryption primitives, avoiding a home-grown cryptographic construction and the pinned Node runtime's Release Candidate Argon2 API. Its wrapper is implemented in JavaScript/WebAssembly, so it adds no Windows native ABI dependency. See [WP-02 dependency review](../dependencies/WP-02.md).
- Use SSH strict trust-on-first-use: an unknown host pauses the handshake and requires explicit approval; a known matching key continues; a changed key blocks the connection. Replacing a trusted key requires a separate explicit reset action. Agent forwarding remains disabled.
- WP-03 must migrate all interim host-key records transactionally to `ssh_host_keys`, verify record count and fingerprints, and only then remove the JSON adapter. Do not import secrets into session definitions or SQLite.

## Acceptance contract for implementation

1. Unknown host produces a challenge containing only a two-minute approval token, canonical host, port, algorithm and SHA-256 fingerprint; it cannot authenticate before explicit approval. At most 64 challenges may be pending, repeated evidence reuses its token, and the public-key blob never crosses renderer IPC.
2. Reject/cancel/expiry before approval terminates the handshake, releases its socket and removes the pending token; approving an unknown key consumes the token before asynchronous persistence, stores that exact public key and permits the connection.
3. A changed key is blocked and never overwrites the saved identity; only the explicit reset-and-approve flow can replace it.
4. A second app process exits before accessing the interim stores. Concurrent approvals through separate adapter instances targeting the same file preserve both previously unknown hosts; concurrent different keys for one endpoint never overwrite the first approval. The shared path queue rejects more than 128 queued operations; the adapter also rejects a file larger than 16 MiB, malformed JSON and unsupported schema versions without trusting any entry.
5. The secret prompt is reachable only after an explicit action, resolves the system directory with Win32 `GetSystemDirectoryW` rather than inherited `SystemRoot`/`WINDIR`, launches the resulting absolute PowerShell path with `shell: false` and `-NoProfile`, uses the Windows native credential dialog, passes no secret in process arguments/stdin/files/renderer IPC/PowerShell output/logs/events, and emits no secret on cancel. Override the environment variables in a test and assert they do not change the resolved executable path. Exercise launch arguments, success, cancellation, malformed/oversized helper output, and helper crash.
6. Default credential persistence contains ciphertext only; unavailable OS encryption, malformed envelopes and corrupt stores fail closed pending explicit reset. Renderer-visible replies/events contain no secret value. A requested safeStorage key rotation is persisted. Concurrent writes and key rotation preserve all entries; mode conversion excludes concurrent writes from snapshot through commit. Test conversion against several test credentials and assert every decrypted value is byte-identical before and after; start a concurrent credential resolution during conversion and assert it waits or observes one complete pre- or post-conversion state, never a mixed vault. Injected conversion failure atomically preserves the prior mode and data.
7. Master-password mode uses only the exact version-1 Argon2id/XChaCha20-Poly1305 profile above; known-answer, tamper, wrong-password and corrupt-envelope cases fail closed. Derivation runs outside main; simulate a slow result and assert that the 30-second timeout terminates the utility process and returns a timeout result, then lock during derivation and assert the process terminates, IPC/OS lock handling stays responsive, and a stale result cannot unlock the vault. Both vault modes block resolution while locked; lock clears the derived-key buffer, master mode restart requires unlock, 15-minute idle and OS session lock/suspend trigger lock. Assert the unlock cooldown starts after five failures, doubles after each additional five, caps at 15 minutes, survives app restart, and resets after a successful unlock. Forgotten-password reset deletes credentials without affecting session definitions.
8. Wrong SSH password is rejected without retrying indefinitely, and auth errors/logs/replies contain no credential material. Close during connect cancels the handshake, clears pending trust decisions and leaves no worker-owned socket/session.
9. Password/key/agent authentication and disconnect cleanup pass against a disposable OpenSSH fixture on Windows before P-03/F-003 is marked verified; Windows OpenSSH agent named-pipe support is unverified until a Windows runtime integration test passes.
10. With `userData` retained, reinstall and same-account data restore preserve readable credentials. A different Windows account cannot decrypt DPAPI-mode records and fails closed; master-password-mode restore succeeds only after the correct master password. Do not claim account portability for DPAPI mode.

These cases must be represented by automated tests before the production adapters are written. Unit/contract tests can use fakes; the final SSH acceptance case must use an OpenSSH server fixture and must not be replaced by a test server implemented with the same SSH library.

## Consequences

WP-02 can be implemented without bringing SQLite forward from WP-03 or adding a native database dependency. The temporary file adapter is a deliberate, bounded departure from the eventual schema, and creates migration work for WP-03. Main-process file I/O is asynchronous; SSH protocol and terminal work remain in the network utility worker. Default DPAPI storage is protected from other Windows users, not same-user malware. Because the current machine has no OpenSSH server installed, the final integration acceptance item is pending an available fixture.
