# WP-02 dependency review — SSH terminal and credentials

**Reviewed:** 2026-10-23
**Status:** versions reviewed and pinned for implementation; runtime acceptance gates remain open. The production dependency audit on 2026-10-23 reported no known vulnerabilities.

## Master-password cryptography

- **Pinned:** `libsodium-wrappers-sumo@0.8.4`, with `libsodium-sumo@0.8.4` resolved and integrity-pinned in `pnpm-lock.yaml`. Both packages are ISC-licensed. Upstream's standard wrapper omits the password-hashing API; the sumo wrapper exposes it, so the adapter must use only the documented high-level password-hash and AEAD functions.
- **Maintenance and security posture:** version 0.8.4 was published about six months before this review; the upstream libsodium project publishes stable maintenance updates and its 1.0.22 release notes include recent security hardening. GitHub reports no published advisories for libsodium.js or libsodium at review time; absence of advisories is not a security guarantee.
- **Runtime and size:** JavaScript/WebAssembly package, no Windows native ABI or install-time build step, supports Node.js. The exact npm registry unpacked sizes are 553,777 bytes for the wrapper and 1,623,551 bytes for `libsodium-sumo` (2,177,328 bytes combined); upstream reports roughly 375 KB minified and gzipped for the sumo distribution (versus 290 KB for standard). The generated workspace inventory records versions and licenses for all 160 installed production/development components as of this review; it does not measure installed size.
- **Fixed profile:** `crypto_pwhash` with `crypto_pwhash_ALG_ARGON2ID13`, opslimit `2`, memlimit `67,108,864` bytes (64 MiB), 16-byte random salt and 32-byte output key. Store the algorithm and exact numeric parameters; accept only this profile in envelope version 1. Use `crypto_aead_xchacha20poly1305_ietf_encrypt/decrypt`, 32-byte key, a fresh random 24-byte nonce per entry and the combined ciphertext with 16-byte tag. Bind envelope version, profile and credential reference as associated data. This uses libsodium's reviewed high-level primitives and avoids the Node 24 Argon2 API's Release Candidate status.
- **Envelope:** version 1 stores profile identifier, algorithm/parameters, salt, authenticated encrypted sentinel, and separately encrypted credential entries. Decoder bounds all input sizes and exact field/encoding lengths before KDF work; unknown versions/profiles and corrupt data fail closed. Any future parameter change requires a new envelope version and migration tests.
- **Execution:** `crypto_pwhash` is synchronous; perform it in a dedicated short-lived Electron utility process, never on main's event loop. Return only the derived key to main, enforce a 30-second bound, and discard/zero late results after a lock generation change.

Sources: [upstream wrapper manifest](https://github.com/jedisct1/libsodium.js/blob/master/package-libsodium-wrappers-sumo.json), [upstream libsodium.js security page](https://github.com/jedisct1/libsodium.js/security), [libsodium project release notes](https://github.com/jedisct1/libsodium/releases), [password hashing documentation](https://doc.libsodium.org/password_hashing/default_phf), [AEAD documentation](https://doc.libsodium.org/secret-key_cryptography/aead), [wrapper package metadata](https://www.npmjs.com/package/libsodium-wrappers-sumo/v/0.8.4), and [sumo package metadata](https://www.npmjs.com/package/libsodium-sumo/v/0.8.4).

## Windows secret entry

Use Windows PowerShell 5.1 `Get-Credential` in a fixed, bundled, one-shot helper. Main obtains the system directory through a repository-owned Node-API bridge to Win32 `GetSystemDirectoryW`; it does not trust inherited `SystemRoot` or `WINDIR`. Append the fixed `WindowsPowerShell\v1.0\powershell.exe` relative path and fail closed if the API fails or the resulting absolute executable is absent. Launch with `shell: false`, fixed arguments including `-NoProfile`, and no execution-policy override. Microsoft documents that Windows PowerShell 5.1 presents a dialog; the helper's private output pipe is the only path carrying its response to main. It receives no secret as arguments or stdin and does not write files. The app uses it for SSH passwords, private-key passphrases, SSH agent usernames (with an empty password), and master-password prompts. Cancellation or helper failure returns no credential. The bridge adds no npm runtime dependency and must be built and tested for the pinned Windows x64 Electron runtime. If the bridge, Windows PowerShell 5.1 or its native prompt is unavailable, fail closed and explain that secret entry is unavailable.

Sources: [Microsoft GetSystemDirectoryW documentation](https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/nf-sysinfoapi-getsystemdirectoryw), [Microsoft Get-Credential documentation](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.security/get-credential?view=powershell-5.1) and [Windows security guidance for credential prompts](https://learn.microsoft.com/en-us/windows/win32/secbp/asking-the-user-for-credentials).

## `ssh2`

- **Pinned:** `ssh2@1.17.0` with its exact integrity value in `pnpm-lock.yaml`.
- **License:** MIT, verified from the upstream package manifest and license.
- **Maintenance:** npm lists 1.17.0 published on 2025-08-20 and package metadata modified on 2026-05-13. The upstream repository has no published GitHub security advisories as checked on this date; this does not replace the project lockfile audit.
- **Runtime support:** the published package declares Node.js `>=10.16.0`; the project pins Node.js 24.14.1 and Electron 45.0.0. Electron 45 bundles Node.js 24.22.0. The SSH implementation is JavaScript and uses Node's crypto APIs, so the supported path has no Node native ABI dependency and supports Windows x64.
- **Optional native code:** the package's install script attempts a `node-gyp` build for an optional crypto binding; optional `cpu-features` also has a native install script. This repository's pnpm `allowBuilds` policy only permits `esbuild` and `node-pty`; keep both SSH-related builds blocked. `corepack pnpm ignored-builds` reports `ssh2` and `cpu-features`; no `.node` artifact was produced in either package, and importing `ssh2` succeeded without the optional binding. This verifies module loading; WP-02B also covers a Windows mock-agent handshake, while disposable OpenSSH interoperability remains unverified.
- **Size:** npm reports 1,119,022 unpacked bytes for `ssh2@1.17.0`. The generated workspace inventory records versions and licenses, not installed size. `asn1` and `bcrypt-pbkdf` are required runtime dependencies.
- **API constraints:** always set `hostVerifier`; upstream defaults to automatic acceptance when it is absent. Preserve upstream algorithm defaults, use a bounded handshake timeout, and keep agent forwarding disabled. The client `agent` option documents Pageant and Cygwin socket paths on Windows; the `createAgent()` documentation also recognizes a Windows pipe path and selects the OpenSSH agent implementation. WP-02B tests the SSH2 client against a temporary local named-pipe agent; actual Windows OpenSSH Authentication Agent service interoperability remains unverified.
- The same pinned SSH client supplies the SFTP subsystem for WP-05A. The implementation uses the documented channel `realpath`, directory-handle and batched `readdir` operations; it adds no protocol package. Verify those calls against the pinned version's [SFTP API reference](https://github.com/mscdex/ssh2/blob/v1.17.0/SFTP.md).

Sources: [upstream package manifest](https://github.com/mscdex/ssh2/blob/v1.17.0/package.json), [upstream license](https://github.com/mscdex/ssh2/blob/v1.17.0/LICENSE), [upstream API documentation](https://github.com/mscdex/ssh2/blob/v1.17.0/README.md), [optional install script](https://github.com/mscdex/ssh2/blob/v1.17.0/install.js), [Electron 45 release notes](https://www.electronjs.org/blog/electron-45-0), and [Electron safeStorage documentation](https://www.electronjs.org/docs/latest/api/safe-storage).

## Win32 system-directory bridge build tool

- **Pinned development dependency:** `node-gyp@12.4.0`, MIT, 1,876,531 unpacked bytes. It is used only to compile the repository-owned `GetSystemDirectoryW` Node-API bridge; it is not included as application runtime code.
- **Compatibility:** its declared Node.js range includes the pinned Node.js 24.14.1. The local build host used Python 3.14.3 and Visual Studio 2022 C++ Build Tools. The bridge targets Electron 45.0.0 x64 with Electron's published headers and uses Node-API version 8.
- **Upgrade constraint:** `node-gyp@13` requires Node.js 24.15 or later, so do not upgrade the build tool without also changing and validating the pinned Node.js toolchain.

Sources: [node-gyp upstream release history](https://github.com/nodejs/node-gyp/releases), [node-gyp upstream build requirements and Electron targeting](https://github.com/nodejs/node-gyp/blob/v12.4.0/README.md), [Node-API ABI guarantees](https://nodejs.org/learn/modules/abi-stability), and [Electron native-module build guidance](https://www.electronjs.org/docs/latest/tutorial/using-native-node-modules).
